# Рентгеновский сцинтилляционный детектор с физическим объективом — модель Geant4

Моделирование детектора непрямого счёта с оптическим увеличением: рентгеновские
кванты просвечивают золотую маску-полоски, вызывают сцинтилляцию в кристалле
YAG(Tb) 6 %, а оптические фотоны собираются **физической двояковыпуклой линзой**
на кремниевой матрице. По хитам в Si строится рентгеновское изображение объекта.

**Объектив** — реальная физическая линза из плавленого кварца (SiO₂), смоделированная
пересечением двух сферических поверхностей. Преломление обрабатывается
`G4OpBoundaryProcess` автоматически — кастомный процесс не нужен.

Сборка: **Geant4 11.3.2**, многопоточный режим (`G4MTRunManager`, 12 потоков).

---

## 1. Что моделируется

Стек вдоль оси Z (рентген летит в направлении +Z):

| Элемент | Толщина | Материал | Позиция / комментарий |
|---|---|---|---|
| Источник γ | — | — | узкий пучок вдоль +Z, `Z = −10 см`, энергия `initialEnergy` |
| Золотая маска (тест-объект) | 15 мкм | `G4_Au` | `Z = 0`; полоски шириной `slitWidth` с такими же зазорами |
| Сцинтиллятор YAG(Tb) 6 % | `scintillatorThickness` | YAG(Tb) 6 % | касается задней грани полосок |
| **Физическая линза** | ~40 мкм (центр) | G4_SILICON_DIOXIDE | `z = lensPlaneZ = 15 мм`, двояковыпуклая, R ≈ 10.06 мм |
| Вакуум | ~40 мм | Galactic (`n = 1`) | линза → детектор |
| Фотодетектор Si | 30 мкм | `G4_Si` | `detectorSize = pixelSize · gridSize · M` ≈ 945 × 945 мкм, в плоскости изображения `z = lensPlaneZ + u·M` |

**Оптические поверхности** — диэлектрик–диэлектрик с полированной поверхностью
(`model = unified`, `polished`). **Миру задан `RINDEX = 1`** — без него
`G4OpBoundaryProcess` убивает фотоны на границе сцинтиллятор→вакуум.

**Физика:** `G4EmLivermorePhysics` (рентгеновский диапазон) + `G4OpticalPhysics`.
Преломление на линзе обрабатывается `G4OpBoundaryProcess` автоматически.

**Оптические свойства сцинтиллятора** YAG(Tb) 6 % (`PMDetectorConstruction.cc`):

| Параметр | Значение |
|---|---|
| Выход фотонов | 22 000 / МэВ |
| Показатель преломления | 1.84 |
| Время сцинтилляции | 65 нс (85 %) + 160 нс (15 %) |
| Длина поглощения (`ABSLENGTH`) | 1500 мкм |
| Спектр | пик ~2.30 эВ (линия Tb³⁺ 543 нм) |

Si сильно поглощает оптические фотоны
(`ABSLENGTH` = 15/10/5 мкм при 1.5/2.5/3.5 эВ): в хиты попадают только
те фотоны, что дожили до передней грани кремния.

## 4. Параметры: `src/global_parameters.cc`

Текущие значения в репозитории:

```cpp
G4double pixelSize               = 3.5 * um;   // размер пикселя (маска и детектор)
G4int    gridSize                = 100;        // число пикселей по оси (поле 350 × 350 мкм)
G4double slitWidth               = 30 * um;    // ширина золотой полоски = ширине зазора
G4int    particlesPerPixel       = 200;        // первичных фотонов на пиксель
G4double scintillatorThickness   = 50 * um;    // толщина сцинтиллятора
G4double initialEnergy           = 8. * keV;   // энергия рентгена

// Оптическая система (реальная линза)
G4double lensMagnification       = 2.7;        // линейное увеличение
G4double lensPlaneZ              = 15.0 * mm;  // центр линзы
G4double lensFocalLength         = 10.93 * mm; // пересчитывается в Construct()
G4double lensCurvatureRadius     = 10.06 * mm; // R = 2(n-1)f
G4double lensCenterThickness     = 40.0 * um;  // толщина по центру (под DOF)
G4double lensRefractiveIndex     = 1.46;       // SiO₂ (плавленый кварц)
G4double lensRadius              = 0.64 * mm;  // апертура ≈ sqrt(R·t)
```

| Параметр | На что влияет |
|---|---|
| `pixelSize` | масштаб всей установки (маска, сцинтиллятор, Si, область сканирования) |
| `gridSize` | поле обзора и число событий |
| `slitWidth` | период золотой маски (полоска + зазор) |
| `particlesPerPixel` | статистика и время счёта |
| `scintillatorThickness` | светособирающая способность, разрешение, SNR |
| `initialEnergy` | энергия рентгеновских фотонов |
| `lensMagnification` | увеличение; **жёстко определяет размер детектора** |
| `lensPlaneZ` | положение линзы; от него зависят `u`, `f`, `v` и `detectorPosZ` |
| `lensRefractiveIndex` | показатель преломления линзы (SiO₂ ≈ 1.46) |
| `lensCenterThickness` | толщина по центру; связана с DOF и апертурой: `r_a ≈ sqrt(R·t)` |

Число событий задаётся автоматически:

```
total_events = gridSize × gridSize × particlesPerPixel
```

**После любого изменения параметров нужен `make`.** При изменении
`gridSize` / `particlesPerPixel` — перегенерация `one.mac`:

```bash
python3 generate_mac.py
```

## 5. Оптическая система: физическая линза

Двояковыпуклая линза из плавленого кварца (SiO₂, n = 1.46). Геометрия —
пересечение двух сферических поверхностей (`G4IntersectionSolid`):

```
1/f = 1/u + 1/v,   M = v/u
```

Расчёт в `PMDetectorConstruction::Construct()`:

```cpp
G4double u = lensPlaneZ - scintillatorPosZ;   // сцинтиллятор → линза
G4double f = u * M / (M + 1.0);               // фокусное расстояние
G4double v = u * M;                           // линза → плоскость изображения

G4double R_lens = 2.0 * (n_lens - 1.0) * f;   // радиус кривизны поверхностей
G4double lensRadius = std::sqrt(R_lens * t_lens);  // апертура (DOF-ограничение)
```

| Физический параметр | Формула | Текущее значение |
|---|---|---|
| `u` (объект → линза) | `lensPlaneZ - scintPosZ` | ≈ 12.5 мм |
| `v` (линза → изображение) | `u · M` | ≈ 33.8 мм |
| `f` (фокусное расстояние) | `u · M / (M + 1)` | ≈ 8.4 мм |
| `R` (радиус кривизны) | `2(n − 1) f` | ≈ 10.06 мм |
| `r_a` (апертура) | `√(R · t)` | ≈ 0.64 мм |
| DOF (Глубина резкости) | `λ / NA²` | ≈ 0.3 мм |

**Преломление** обрабатывается автоматически через `G4OpBoundaryProcess`
на поверхности линзы — кастомный процесс не требуется.

## 6. Одинарный прогон

```bash
cd build
python3 generate_mac.py     # пишет one.mac с нужным числом событий
./sim one.mac               # результат: hits_data.csv в каталоге сборки
```

`generate_mac.py` читает `gridSize` и `particlesPerPixel` из
`src/global_parameters.cc` и генерирует `one.mac`.

Интерактивный режим с графикой:

```bash
./sim                       # откроет OGL-визуализацию (vis.mac)
```

### Как работает генератор событий

Пучок сканирует поле по пиксельной сетке: `particlesPerPixel` первичных
фотонов на каждый пиксель `gridSize × gridSize`. Точка входа каждого
фотона разыгрывается равномерно по площади пикселя — чтобы избежать
периодической решётки на гистограмме, которая портит оценку шума.
Счётчик пикселей общий для всех потоков, по заполнении поля вызывается
`AbortRun()` — реальное число событий всегда точно равно `gridSize² × particlesPerPixel`.

### Формат `hits_data.csv`

Разделитель — табуляция:

```
Energy_eV	PosX_um	PosY_um	Type	EventID
```

В файл попадают все частицы, долетевшие до Si-детектора. Анализ
использует только строки с `Type = opticalphoton`. Координаты —
**в плоскости изображения**; для пересчёта в плоскость объекта
нужно разделить на `lensMagnification`.

## 8. Анализ одного прогона

```bash
cd build
python3 xray_image.py                    # анализирует ./hits_data.csv
python3 xray_image.py path/to/data.csv   # явный путь
```

Скрипт читает геометрию из `src/global_parameters.cc` (через `sim_params.py`),
фильтрует оптические фотоны, пересчитывает координаты в плоскость объекта
делением на `lensMagnification` (со знаком инверсии: `x_obj = −x_img / M`)
и строит 2D-гистограмму. Размер бина по умолчанию — `pixelSize = 3.5 мкм`,
то есть 1 пиксель изображения = 1 пиксель исходной маски (100 × 100).

Выходные файлы рядом с CSV:

- `xray_image.png` — 2D-изображение;
- `xray_image.npz` — данные и параметры сетки.

**Важные детали:**

1. FOV в плоскости объекта — `pixelSize · gridSize = 350 мкм`.
   FOV на детекторе — `pixelSize · gridSize · M ≈ 945 мкм`.
   Скрипт автоматически пересчитывает координаты в плоскость объекта.
2. Знак инверзии одиночной собирающей линзы **учитывается**:
   `x_obj = −x_img / M`.
3. По умолчанию `bin_size = pixelSize = 3.5 µm` → изображение 100 × 100.
   Для разрешения уровня отдельного пикселя матрицы замените в скрипте:

   ```python
   bin_size = 1.28     # мкм, эффективный пиксель CMOS с M = 2.7 → 274 × 274
   ```

   При этом на один объектный пиксель (3.5 µm) приходится ~2.7 эффективных
   пикселя — без достаточной статистики картинка будет шумной.

## 11. Важные предупреждения

1. **Материал мира обязан иметь `RINDEX`** (в `PMDetectorConstruction.cc`
   у `Galactic` стоит `RINDEX = 1`). Без него `G4OpBoundaryProcess` на
   границе сцинтиллятор→вакуум убивает все треки оптических фотонов —
   изображение не строится (ошибок в логе нет, просто ноль хитов).
2. **Размер детектора жёстко привязан к увеличению**:
   `detectorSize = pixelSize · gridSize · lensMagnification`. Меняя `M`,
   меняйте и размер Si, иначе часть изображения обрежется.
3. **Детектор обязан стоять в плоскости изображения**:
   `detectorPosZ = lensPlaneZ + u·M`. Иное положение приведёт к сильному
   размытию (пятно размером с апертуру линзы).
4. **Число событий** `total_events = gridSize² × particlesPerPixel`
   задаётся в `one.mac`. При изменении `gridSize` / `particlesPerPixel`
   необходима перегенерация: `python3 generate_mac.py`.
5. `hits_data.csv` создаётся в **каталоге запуска** (обычно `build/`).
   Перед следующим прогоном его нужно удалить или переименовать.
6. **Файла `output.root` нет** — ветка ROOT включена в `CMakeLists.txt`,
   но `G4RootAnalysisManager` в коде не используется. Единственный источник
   данных для анализа — `hits_data.csv`.
7. Скрипты анализа используют `grep`/`awk` — работают под Linux/WSL, в
   чистом Windows PowerShell не запустятся.
8. **Физическая линза не учитывает хроматическую аберрацию** —
   показатель преломления принят постоянным (n = 1.46). Сферическая
   аберрация частично учтена через ограничение апертуры `r_a ≈ √(R·t)`
   (глубина резкости ≈ 0.3 мм). Для точных количественных расчётов
   введите хроматический спектр RINDEX или PSF в постобработке.
9. **Апертура линзы `lensRadius` — компромисс**: маленькая даёт мало
   фотонов и снижает SNR, большая — выходит за пределы DOF.
   Разумный диапазон — `lensRadius ≈ √(R · t_center)`.
